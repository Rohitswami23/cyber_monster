# Day 2: Web Application Basics & Browser Developer Tools

## 1. The Front-End Triad
Web applications consist of three primary client-side components:
- **HTML (HyperText Markup Language):** The skeleton of the page (buttons, text boxes, headers).
- **CSS (Cascading Style Sheets):** The styling, layout, colors, and visual presentation.
- **JavaScript (JS):** The engine/logic running inside your browser (interactivity, sending background data requests, dynamic UI rendering).
---
## 2. DevTools Breakdown (The Hacker's Toolkit)

### A. Elements / Inspector Tab
* **What it does:** Displays the live DOM (HTML + CSS) currently active in the browser.
* **Cybersecurity Tip:** Web attackers look at **Page Source** to find developer comments (`<!-- todo: remove admin endpoint -->`), hidden input fields, or inline script files. They use the **Inspector** to inspect live form elements, un-hide disabled buttons (`disabled="true"` -> delete tag), or modify CSS to expose hidden UI elements.

### B. Debugger / Sources Tab
* **What it does:** Allows you to inspect and debug JavaScript files running on the target application.
* **Key Concept (Breakpoints):** A **breakpoint** pauses JavaScript execution at a specific line of code so you can inspect memory variables, step through execution flow, or view hidden variables before they are sent.
* **Pentesting Use Case:** Analyzing obfuscated client-side authentication checks or understanding how dynamic data is calculated before being sent to an API endpoint.

### C. Network Tab
* **What it does:** Records every single HTTP request and response made between your browser and the web server (GET, POST, static assets, APIs).
* **Pentesting Use Case:** Seeing hidden API requests (`/api/v1/user/data`), inspecting request headers, examining POST body data (like credentials submitted in forms), and viewing raw JSON/XML responses returned by the server.

### D. Application / Storage Tab
Stores client-side data generated by the server or browser scripts:
* **Cookies:** Key-value pairs stored in the browser (often used for session IDs like `PHPSESSID` or `JWT` tokens). If an attacker steals these via XSS, they can hijack user accounts.
* **Local Storage:** Persistent key-value storage in the browser that remains even after the tab is closed.
* **Session Storage:** Temporary key-value storage that expires as soon as the browser tab is closed.
* **Cache Storage:** Saves static assets (images, CSS, JS) locally to reduce network usage and speed up page load times.
